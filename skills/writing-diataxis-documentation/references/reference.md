# Reference

Need: give a competent practitioner factual certainty while working.

- Let the described machinery determine the scope and structure. Mirror its
  logical relationships so the documentation acts like a map of the product.
- Describe and only describe: neutral, austere, authoritative, precise, and
  complete for the declared scope.
- Use stable, repeated patterns that make facts easy to consult.
- Include succinct examples only to illustrate usage or context.
- Link procedures and conceptual discussion instead of embedding them.

## Language

- State facts directly: "`timeout` defaults to `30s`."
- List valid values: "Valid modes are `active`, `passive`, and `off`."
- State constraints: "Don't combine `force` with `dry-run`."

Reject narrative instruction, interpretation, opinion, or explanation that
interrupts consultation.
